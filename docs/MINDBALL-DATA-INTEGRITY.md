# 心力球记录可靠性审查 · 2026-10-28

本候选基于 `v0.43.1`（`923218c`）。范围是本机记录写入、整理进度和异常响应，不改变录音开关、转写/整理服务配置、账号同步、留存期限或版本号。没有安装真机、启动录音、访问真实音频/转写/凭据、调用云模型或发布 APK。

## 已复现并修复

| 触发场景 | 原行为 | 候选行为 |
|---|---|---|
| 原文已写入日文件，进程在删除待转写音频前终止；同一区间再次转写 | 重复追加原文，分钟数和片段数膨胀 | 按原有音频文件名对应的 `start`/`end` 去重，保留首次原文；重复追加不重写文件 |
| 一个较早片段延迟返回，而更晚片段已经整理 | 最大结束时间不变，不再触发整理 | 使用追加数组的 `summarizedSegmentCount` 检查新增内容；页面未整理数量使用同一判断 |
| 整理服务故障持续到某日退出最近三个记录日 | 该日可能永远不在重试候选里 | 扫描全部仍保留的记录日；只请求确有新增片段的日 |
| 已有日文件损坏或结构不符，再追加原文、勾选待办或保存整理结果 | 读取失败被当成空 JSON，旧文件可能被覆盖 | 写入路径严格读取；失败即停止，保留原件，处理轮次报告本机读写错误 |
| 转写响应 HTTP 200，但缺少 `text` 或返回非字符串 | 被当成空文字，或转换成伪原文 | 抛出解析错误，走已有失败路径，不进入成功后的音频删除分支 |
| 整理响应 JSON 缺少 `items` 或不是数组 | 当成空时间线，覆盖现有事项 | 抛出解析错误，保留上次时间线和整理进度 |

正常的 `{"text":""}` 仍表示服务明确返回空原文；正常的 `{"items":[]}` 仍是合法空时间线。候选不试图推断模型内容是否正确。

## 旧文件兼容与写入边界

- 不运行全量迁移。读取旧文件不会写磁盘；首次追加保留所有旧片段（包括已有重复片段）、原文字段、待办完成标记、原时间线和未知字段。后续正常整理仍会替换时间线。
- 首次追加前，使用旧 `summarizedThrough` 推导已整理片段数并添加 `summarizedSegmentCount`。新片段即使结束时间更早，也在计数水位之后。旧的 `summarizedThrough` 和 `summarizedAt` 继续保存。
- 整理成功只标记本次请求所依据快照的片段数。提交时在同一锁内重读最新文件，保留等待期间的待办勾选/撤销和新增原文；后来新增的片段仍待整理。
- 临时文件写入后同步文件描述符，再重命名替换。写入失败和旧文件不可读时，合成测试逐字节确认原件不变。这不是断电恢复或真机文件系统的完整保证。
- `WORK` 单线程串行处理网络轮次，`LOCK` 保护日文件修改；清除全部递增 `epoch`，旧轮次不能重新写回原文或时间线。
- 不删除历史重复片段，也不能凭旧的时间水位辨认升级前已经漏掉的旧片段。候选避免继续造成同类问题，不宣称自动修复所有历史结果。
- `summarizedSegmentCount` 以日文件只追加为前提。若使用旧版本继续录音，再回到此候选，应重新验证进度；此次没有设计双向降级迁移。

## 审查到的现行语义与剩余问题

| 项目 | 实际实现与范围 |
|---|---|
| 按日统计 | 只统计已转写保存的片段，用 `end-start` 求和并四舍五入成分钟；待转写、正在录制及被判静音的片段不在其中，不等于全天麦克风开启时长或说话时长 |
| 跨午夜 | 整段原文和时长归录音开始日；23:55–00:05 的 10 分钟全部归前一天。日期使用转写时系统时区；跨时区重试也可能改变归属。不按午夜切割音频或推断逐句时间。此次未改变 |
| 延迟转写 | 新增的旧片段能触发整理；片段存储和原文显示仍按追加顺序，晚到片段不保证按录音时间重排 |
| 待办完成 | `done` 以规范化标题的 Java hash 为键；空白/标点变化可对应，语义改写不保证对应，也没有独立任务 ID。并发完成标记保存已验证；模型重写或漏报时，整个时间线仍可能替换已有待办 |
| 待办留存 | 看板只展示近 7 天，日期入口只列最近 14 个记录日；文件保留 30 个日历日。未完成待办也随到期日文件删除。长期待办需要独立持久模型，不能默默突破现有删除承诺 |
| 音频删除 | 全段少于 8 秒过阈值声音直接删除；手动立即整理保留至少 1 秒过阈值且可关闭的片段。转写成功后删除音频；连续失败音频按开始时间最多约 48 小时，进程截断的 `recording-*` 文件会清理。部分文件被拒绝后，后续文件成功仍可能触发拒绝文件删除（现行策略） |
| 原文/输入上限 | 每片段本机保存最多 20,000 字符，整理输入最多约 300,000 字符，时间线最多 200 条。超限会截断；整理水位不等于所有原文都进入模型或所有事项都被提取。此次未改变 |
| 本机留存与云处理 | 音频发送到配置的转写服务，原文发送到 DeepSeek；Key/服务设置可经已有账号同步。私有目录和禁备份不代表全离线推理 |
| 损坏记录恢复 | 候选阻止继续覆盖，并不自动修复损坏文件。只读页面仍可能显示空记录，处理失败提示会说明本机读写错误；恢复工具和更明确的不可读占位可另行实现 |

设置页现有“录音和记录保留 30 天”合并文案未准确区分失败音频约 48 小时与文本 30 天；上表按实际代码列出，不将该文案作为数据保证。

## 验证

- 在基线实现运行合成文件回归：重复追加、损坏覆盖、旧片段漏整理三项均失败。
- 在原响应解析实现运行回环服务回归：缺失/非字符串 `text`、缺失/非数组 `items` 四项均失败。假服务只监听 `127.0.0.1`，只处理合成文件和凭据。
- 修复后验证：首次原文与分钟数不重复；旧文件只读不改写、未知字段/完成标记保留；混合“旧的未整理尾段 + 新增迟到片段”数量正确；临时写入失败和损坏/类型不符原件保留；等待期间勾选/撤销保留；清除后迟到结果被拒绝；合法空响应兼容。
- 全仓库 `testDebugUnitTest lintDebug lintRelease assembleDebug assembleRelease` 离线通过：app 303 项、billing-lab 23 项 JVM 测试，0 失败/0 错误；Debug 和 Release lint 均 0 错误。构建显式移除正式签名目录，Release 为未签名候选。
- lint 仍有既有项目警告/提示；JDK/Android SDK XML 版本与 Gradle 弃用提示也未在此范围升级。
