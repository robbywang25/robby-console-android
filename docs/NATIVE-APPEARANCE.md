# 原生界面

当前版本采用 Liquid Glass 风格（v0.4），规格和取舍见 [PRODUCT-STYLE.md](PRODUCT-STYLE.md)。下方 v0.3.x 的记录保留为历史，不是当前默认样式。Android 使用平台原生 View 和矢量资源，不引入第三方 UI 库。

## 组件

- `ConsoleTheme` 统一配色和材质：天空渐变背景；内容卡片 24dp，半透明，顶部带高光边；控制层玻璃包括圆形按钮、Dock 和选中胶囊；胶囊形按钮；14dp 输入框；对话框是完全不透明的玻璃面，带高光边。Find 上的跨窗口模糊没有生效，哪怕 98% 不透明也会透出背后页面的文字，所以完全不做透明。还包括状态色点、类别着色图标块，以及按压下沉回弹的效果。
- `GlassPane` 是底部 Dock。Android 12 及以上会把下方页面录制到独立的 RenderNode 上并做模糊，每帧绘制前重新录制，但不主动刷新 Dock 自身，所以不会额外驱动帧。它同时负责选中胶囊的布局和滑动动画。
- 页面结构：状态栏下面是固定页头。Tab 根页左侧是日期或「God 工作台」小字加大标题，右侧是圆形操作按钮；详情页左边是返回圆钮，中间是居中标题，右边是刷新或「+」圆钮。滚动内容在页头下方淡出，并一直延伸到悬浮 Dock 后面。
- 总览：第一张卡片回答服务健康（几项在线，几项未在线或状态未知），下面是云实例和域名两张指标卡，点击可进入详情，最后是待办提醒。
- 详情数据卡：键值行之间有细分隔线；状态值前加色点，文字始终保留；快照时间显示为带色点的玻璃胶囊。
- 列表：分组卡片，每行是类别着色图标块、标题、一行说明和箭头。仅展示信息的行没有箭头，也不可点击。
- 账本：「记一笔」在页头的「+」圆钮上；上一页和下一页并排；编辑、人员、最近删除、核实提交、切换账本放在同一张分组列表里。准备、确认、提交、回执与恢复流程不变。
- 降级：Android 11、关闭动画、省电模式及高对比文字模式下，不做实时模糊、不做按压和过渡动画；高对比模式下背景改为纯色，卡片加描边。
- 大字体下指标卡和键值行改为上下堆叠，控件至少 48dp，数据行允许增长，不截断金额。

主题跟随设备浅色/深色设置。业务内容继续在后台清除，正式登录界面继续使用 `FLAG_SECURE`。

## 独立视觉预览

Debug 构建是独立的 `wang.robby.console.android.preview` 应用，显示“界面预览 · 合成数据”，数据来源只在 `src/debug` 中。登录和写入被禁用，预览不接收正式 App Link。Release 的 `PreviewMode` 固定关闭，APK 不包含预览 Activity 或合成数据。

```sh
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n wang.robby.console.android.preview/wang.robby.console.android.PreviewActivity
adb shell 'am start -n wang.robby.console.android.preview/wang.robby.console.android.PreviewActivity\$Dark'
adb shell 'am start -n wang.robby.console.android.preview/wang.robby.console.android.PreviewActivity\$Large'
```

这些入口只覆盖预览应用的显示配置，不修改设备的全局主题或字体。可检查首页、五栏导航、功能列表、返回、滚动、设置和已有示例详情。未提供合成数据的功能显示预览限制，不请求真实服务。

视觉验收不能替代真实登录或业务数据验收；两者分别记录在发布说明中。

## v0.5.0：App 内一键更新（2026-10-15）

「关于」页的版本号下方是更新区：
- 第一次打开「关于」时检查一次 GitHub Releases，检查过程中显示「正在检查…」；
- 已是最新版本时，显示一行「检查新版本 · 已是最新版本」，点按可以重新检查；
- 有新版本时，显示「发现新版本」卡片，包括版本号、Release 主题、正文第一段、安装包大小和发布日期，以及一个「立即更新」主按钮。

点「立即更新」后的流程：
- 如果还没有「安装未知应用」权限，先弹窗引导你去系统设置；打开后返回，会自动继续；
- 下载时卡片里显示进度条和百分比，下载完成后显示「正在校验」；
- 校验通过后交给系统安装器，提示「请在系统弹窗中确认安装」；
- 如果取消或失败，卡片显示原因，按钮变成「重试更新」。

实现位置：
- `AppUpdate`：负责查询、按域名白名单跟随跳转并下载、核对 SHA256SUMS、检查包名、versionCode 和签名，最后提交 PackageInstaller 会话。
- `UpdateReceiver`：不对外暴露，接收安装状态并打开系统的确认页。
- 预览版用合成的新版本数据，点更新时重装自身来走一遍系统安装流程；Debug 构建额外支持 `--ez preview_real_update true`，让预览版假装是 0.3.0，去走真实的 GitHub 链路。

增量更新的评估：Android 只给应用商店做增量更新，自己分发的 App 用不上，要自己做就得为每个旧版本各生成一份补丁，在 App 里合成新包并校验整包的 SHA256。0.3.6 和 0.4.0 两个安装包对比下来，整包 0.24 MB，其中 93% 是未压缩的 `classes.dex`，两版之间它和 `resources.arsc` 整个都变了，增量一次最多省一两百 KB。做增量还要额外维护补丁生成、合成和回退逻辑，并引入解压库，所以本版只做全量更新。下载完成后的 SHA256 校验和以后的增量合成可以共用。

验证：`check.sh` 全部通过，单元测试 66 项，其中新增 6 项，覆盖版本筛选、版本比较、校验文件解析、域名白名单、标题和摘要。在 Find（Android 16）上：
- 预览版合成流程：依次检查了检查中、更新卡片、权限引导（开关由用户在系统设置里打开）、返回后自动继续、下载进度、ColorOS 的「已安装相同版本」确认和扫描页。最终 App 自己发起的安装确实完成，包的 lastUpdateTime 更新了，缓存里的安装包也删掉了。取消安装后，卡片显示「已取消安装」和「重试更新」。深色模式也检查过。
- 真实 GitHub 链路（Debug 开关）：以 0.3.0 的身份查到了 v0.4.0，标题、摘要、235 KB 和发布日期都正确。通过 `release-assets.githubusercontent.com` 跳转下载后，SHA256 校验通过，安装包能解析，签名信息能读出来，最后按预期因为包名不同停在「安装包不属于本应用」。

未验证：
- 正式包之间真实的签名一致比对和升级安装，要等 0.5.0 之后的下一个版本发布时才会第一次真正跑到；
- ColorOS 对正式包的 App 内安装可能也会出现扫描页，需要你在手机上确认。

- **个人头像**：在「我」页点头像，可以从相册选择或移除头像。优先使用系统照片选择器（`android.provider.action.PICK_IMAGES`，不需要存储权限），不可用时退回 `ACTION_GET_CONTENT`。`Avatar` 会把图片解码、居中裁剪、缩放到 512px，以 JPEG 存进 `filesDir`，进程内缓存一份；资料卡片和「我」这一栏显示圆形头像，选中这一栏时头像外加一圈描边。
- **总览密度**：
  - 三项数字（在线服务、云实例、域名资产）并排放进一张卡片，各自可点进详情；
  - 服务状态、提醒数和快照时间改成卡片内的一排胶囊，总览不再单独显示快照时间那一行；
  - 有提醒时才显示「待办提醒」卡片，提醒行也更紧凑；
  - 删除与 Dock 重复的「全部功能」；「常用」图标从 48dp 缩到 40dp，分区标题的上下间距也收紧。

验证：见提交时的 `check.sh` 结果。没有做预览版真机验收，头像选择流程和总览在真实数据下的排版需要在真机上确认。

## v0.9.0：可组合的看板（2026-10-15）

- 总览只保留「看板」和「常用」。看板的标题右侧有「编辑」，点进去是编辑看板页：在「已添加」里用开关移除卡片、用箭头调整顺序，在「可添加」里用开关加回卡片，也可以「恢复默认组合」。修改立即生效，组合以卡片 id 列表的形式保存在 SharedPreferences 的 `dashboard` 键里，只存布局，不存数据。
- 卡片目录在 `Dashboard.ALL`：
  - 服务状态（整行）、待办提醒（整行）、云实例、域名资产：都读取 `overview`；
  - OpenAI 用量：`openai/usage`；
  - 访问：`analytics/overview`；
  - OKX 账户：`okx/overview`；
  - 云剪贴板：`clipboard`；
  - 关注行情（整行）：`market`。

  默认组合是服务状态、云实例、域名资产、待办提醒。
- 读取方式：同一路径只请求一次，结果用进程内的快照缓存；渲染前按对应功能的合同做兼容检查。读取失败只在相关卡片上显示「暂不可读」；如果会话已失效，就回到登录页。右上角的刷新按钮会重新读取所有卡片。
- `DashboardTest` 覆盖解析、去重、开关、排序、路径合并，并检查每张卡片对应的都是已发布的功能。

验证：见 `check.sh`。没有做预览版真机验收；需要额外权限的卡片（OKX、访问）在当前账号权限下能否读取，要在真机上确认。

## v0.10.0：Token 额度与网页同款排版（2026-10-15）

- **Token 额度**：新增功能 `tokens`，读取 `GET tokens/quotas`，需要 `god.mobile.tokens.read` 授权（iOS 已在使用同一路由，合同 schemaVersion 1）。页面先显示额度总览（已更新、需处理、即将重置），再按平台分组显示账号。
  - 新鲜读数显示剩余百分比进度条（≥50% 绿、20～50% 琥珀、<20% 红）和重置倒计时；过期读数标「上次」，不画进度条。
  - 「即将重置」沿用网页规则（`TokensModel.resettingSoon`，见 `TokensModelTest`）。
  - 有余额曲线时，显示近 1 小时剩余。
- **看板**：新增「Token 额度」整行卡片，列出各账号最紧张的那个额度和重置倒计时，可以在「编辑看板」里添加；在服务端开放权限前不放进默认组合（0.10.1 已加入默认组合）。
- **授权**：认证服务还没有给 `robby-console-android` 客户端登记 `god.mobile.tokens.read`，而登录请求里带了未登记的 scope 会被拒绝，所以 0.10.0 暂不申请这个 scope。Token 额度页和看板卡片遇到 403 时，会明确提示「服务端还没给 Android 开放」；该卡片也不放进默认组合。服务端登记后，再发一版把它加进 `AuthSession.SCOPES`。届时已保存的会话 scope 对不上，需要重新登录一次。（0.10.1 已补上，见下节。）
- **网页同款排版**（来源：site-admin 各页面）：
  - 访问统计增加累计数据、每日访问柱状图（`MiniBars`）和地区分布，站点行显示 HTTP 状态码和耗时；
  - OpenAI 用量增加 30 天每日 Token 柱状图，以及「近 7 个完整日」的涨跌、缓存占比、峰值日、主要模型；
  - 基础设施、登录审计、目录同步、公众号、凭据、剪贴板、工程、卡片、Prompt 都在顶部加了数字网格，有边界说明的页面在页尾补了一行。

验证：见 `check.sh`。真实账号读取要等服务端登记 scope、应用加上它并重新登录后才能验收。

## v0.10.1：申请 Token 额度授权（2026-10-15）

- **服务端**：2026-10-15 在 Authelia 的 `robby-console-android` 客户端 scopes 末尾登记 `god.mobile.tokens.read`，只改这一行；iOS 客户端和其他字段不变。移动接口（`jwt-access-token.js`）此前已经接受 Android 客户端的令牌，`tokens/quotas` 只要求 owner 加这一项 scope。
- **授权**：`AuthSession.SCOPES` 末尾加 `god.mobile.tokens.read`。本机保存的会话按 scope 严格比对（`validateStored`），0.10.0 及更早的会话少这一项，`hasSession()` 判为无效，回到登录页，需要重新登录一次。更新记录里写明了这一点。
- **看板**：默认组合加入 Token 额度整行卡片（`Dashboard.DEFAULT` 末尾，`DashboardTest` 同步）。只影响从没保存过组合的人。
- **403 文案**：Token 额度遇到 403 时，提示改为「这次登录没有 Token 额度读取权限，请在「我」里退出后重新登录」。

验证：`check.sh` 通过（81 项 JVM 测试、lint 0 错误、正式证书签名）。服务端改动后，在未登录状态下向认证服务发起带这项 scope 的授权请求，现在会进入登录流程，改动前返回 `invalid_scope`。按用户偏好跳过了预览版真机验收；登录后无法截图，真实读取由用户在手机上确认。
