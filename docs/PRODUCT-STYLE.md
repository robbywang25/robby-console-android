# God Android 产品风格基准

以产品拥有者最新明确反馈为准。历史方案保留在变更记录中，不能覆盖当前决定；这份规范只约束本应用，不自动更改其他产品的主题。

## 当前视觉规格（v0.4 Liquid Glass）

2026-10-15 产品拥有者要求参考 TodayAI 的设计、以微信产品经理的视角、用 Liquid Glass 设计语言整体迭代。此前「白/黑纯色背景、无文字纯图标底栏、不用玻璃与渐变」的规格由本节取代，保留在变更记录中。

- 背景是柔和的天空渐变：浅色由淡蓝过渡到暖白，深色由深海军蓝过渡到黑。高对比文字模式改为纯色背景。
- 层级分两层：内容层是半透明大圆角卡片（24dp），顶部带高光边；控制层浮在内容上方，包括顶部圆形按钮、底部 Dock 和选中胶囊。只有控制层使用玻璃高光，数据卡片保持高不透明度，以保证可读。
- 腾讯蓝 `#0052D9` 只用于主操作和链接；深色前景强调 `#4582E6`。金额和普通数据保持中性色。
- 状态值前加一个色点，仅作辅助：绿色表示正常，琥珀色表示需关注或数据陈旧，红色表示不可用或异常。状态文字始终保留，颜色不单独承载含义。
- 功能图标统一为单色线性图标，放在按类别淡着色的圆角方块里。
- 复用 God 网页光环人物 Logo，保留来源与几何，不另造品牌。
- 底部是悬浮的玻璃 Dock，三栏「总览 / 功能 / 我」，为「图标 + 文字」，选中项由一块玻璃胶囊托住，切换时胶囊会滑向新位置。再点一次已选中的标签（双击同理）回到这一栏的首页，已在首页时滚回顶部。Android 12 及以上会实时模糊 Dock 下方滚过的内容；Android 11、关闭动画、省电模式和高对比模式下改为近乎不透明的同色底。
- 「我 → 外观 → 状态栏」四种模式：不隐藏、只隐藏（页面不动）、隐藏并上移、灵动岛（纯黑胶囊包住摄像头开孔，显示时间和电量）；隐藏时从顶端下滑临时显示。（2026-10-20）
- Tab 首页顶部不显示页签名（底部 Dock 已标明当前页签），登录后首页没有顶栏：总览从看板开始，功能从搜索框开始，我从账号卡片开始。（2026-10-20）
- 三个 Tab 首页全屏显示：内容一直延伸到屏幕顶端，上滑时从状态栏下面穿过并渐隐。详情页的顶栏固定，返回和主操作始终可点。（2026-10-19）
- 「我 → 外观」照 iOS 26 的 Liquid Glass 设置：开关关闭后全部改为不透明表面、Dock 不模糊；打开时用滑块在「清透 ↔ 默认 ↔ 着色」之间调节，默认档就是上面的规格。清透端底色几乎全透明（浅色卡片约 5%），Dock 模糊从 22dp 降到 4dp、高光只留一点，靠高光边和文字区分；高对比度文字下固定不透明。（2026-10-19）
- 功能可以隐藏：「功能」和「我 → 管理」里长按出现「打开 / 隐藏」，隐藏的功能收进「我 → 已隐藏的功能」，在那里点「显示」放回原处。暂未接通的功能（真机只读验收读不通或数据源未配置）默认隐藏并注明原因；常用不推荐隐藏的功能，搜索到隐藏功能时给出入口。（2026-10-19）
- 第五栏显示为「我」（内部标识仍是「设置」），对应微信里「我」的位置：顶部是账号卡片，下面是管理和关于。

## 设计取舍（微信产品经理视角）

- **先给结论：**总览第一屏回答「服务是否都在线、有几项要处理」，再给数字；三项指标都存在时才计算未在线和状态未知的数量，否则显示「状态未知」。
- **数字即入口：**总览里的服务、实例、域名指标可以直接点开对应详情，不必再去别的 Tab 找。
- **一个主操作：**账本里「记一笔」放在顶部的「+」圆形按钮上，在长列表的任何位置都能一键触达；其余管理动作收进同一张分组列表。
- **红点只代表「有新版本可以装」：**App 在前台时每 30 分钟以内静默查一次 GitHub Releases，查到比已装版本更新的发布，「我」和「关于 God」才出现微信红 `#FA5151` 的小点，装上之后自然消失。升级后的更新说明不再单独用红点提示（用 adb 或其他途径装的新版本不会亮红点）。不用红点做营销或催促。
- **说明收进 ⓘ：**页面底部纯说明、没有状态和数字的文字（来源说明、「仍在网页管理端」、免责声明等）收进一个小 ⓘ，点开在原处展开；同步时间、缺数据计数这类状态仍直接显示。
- **更新记录写给用户看：**在「我 → 关于」里，当前版本单独一张卡片默认展开，历史版本收进一张分组列表、点开就地展开；每版有一句话主题加最多 6 条，用用户能感知的语言写，技术细节留给 GitHub Release。
- **更新就在原地完成：**「关于」页打开时检查一次新版本（只在这里检查，不在后台检查），有新版本就在版本号下方出现更新卡片，点「立即更新」后在 App 里完成下载、校验和系统安装，不跳转浏览器。安装包只有约 0.2 MB，所以只做全量更新；增量更新的评估结论见 NATIVE-APPEARANCE。
- **监控页先给结论，异常可直达：**运行状态页第一行回答「全部符合预期」还是「N 项需要关注」，并点名问题项；点问题项会跳到对应行并展开。状态名称与 status.robby.wang 一致；没检测到的站点显示「未检测」，不算正常也不算异常。
- **一行一条，点开看全：**列表类页面一条记录占一行，包括标题、右侧关键值和一行摘要；其余字段点开就地展开，不藏数据也不截断数值。汇总数字用多列网格，数据来源合并成一排胶囊，空状态只占一行。键值行 38dp 高，只有可点的行保证 48dp 触控区。
- **总览只有看板和常用：**看板由用户自己组合功能卡片（服务状态、提醒、实例、域名、OpenAI、访问、OKX、剪贴板、行情、Token 额度），可以开关和排序；整行卡片独占一行，小卡片两张并排；每张卡片只给 1～3 个关键数字，点进对应详情。底部 Dock 已有的入口不在首页重复列出。登录后的总览没有日期行和大标题，也没有刷新按钮和「看板 / 编辑」行：在页面顶部下拉刷新看板（拉到位有触感提示，图标转到所有卡片读完），长按任意看板卡片进入「编辑看板」；读屏用户用对应的无障碍操作完成同样的事。
- **功能按最近使用排序：**「功能」保留三个分区，区内最近打开的排最前，没打开过的按目录顺序在后；搜索结果同样排序。（2026-10-19）
- **DeepSeek 模型写清来源：**「功能 → 工具 → DeepSeek 模型」一行一个官方模型，右侧是它在 deepseek.robby.wang 的状态（可用 / 本站未启用 / 待核验 / 官方未列出），点开分「官方返回」「价格与能力 · 本站登记」「状态」三段；官方返回的每个字段都列出来，价格只用本站登记的单价并写明核对日期、有效期和来源，没登记的写「待核验」，不显示成 0。页面底部可展开接口完整返回。（2026-10-19）
- **功能一页可搜：**洞察、资产、工具是「功能」tab 里的三个分区（与 iOS 一致）；顶部搜索框只搜内置功能目录（名称、描述、标识和中英文别名，所有关键词都要命中，忽略大小写与全半角），不搜账号数据，不保存搜索词。
- **刷新只靠下拉：**所有数据页在顶部下拉刷新，没有刷新按钮；转圈直到这一页的读取完成。
- **Token 额度与 tokens 网页一致：**没有额度总览，只列已接入账号（不含 ChatGPT Dots / 聊天），按 OpenAI / Claude / Grok / Cursor / TodayAI 分组、组内顺序固定。每张卡片依次是身份、产品与右上角数值、价格与套餐、Points 与重置卡（Codex）或 5 小时 / 每周余额（Claude）、节奏提示、近 1 小时曲线、重置时间、重置卡明细；文字和判定移植自网页的 renderOverview。
- **看板也有时钟和日历：**「时区时钟」不读服务器，每秒在本机走，默认 Tibo（美西）和北京时间，编辑看板里可以增删改名（最多 6 个，名称最多 12 字），每行显示与本机的时差；「重置日历」列出接下来最多 4 次重置，一周内只写星期几，账号只写邮箱 @ 前面的部分。
- **编辑看板靠拖动：**已添加的卡片每行右侧一个 ≡ 手柄，按住拖动，经过的卡片让位并有轻微触感，松手即保存；读屏用户用「上移 / 下移」无障碍操作。
- **常用按习惯排：**每打开一个功能记 1 分，分数每 7 天减半；常用取分数最高的 4 个，同分取最近的，不够时用旅行记账、云剪贴板、OpenAI 用量、域名资产补齐。只在本机记功能编号和时间。
- **先有列表再有数字：**看板的 Token 卡片在读取时，先按上次显示的账号（只存账号编号和产品名）画出各行，额度位置用跳动的占位条，读到后再填。看板的几个读取并行进行；读完的连接留在连接池里复用，省掉后续请求的握手。
- **小组件只放公开信息：**God 小组件（桌面和锁屏通用，`widgetCategory` 含 keyguard）和快捷设置磁贴只显示 God 图标、Tibo 的公开重置预告和系统驱动的倒计时，绝不显示余额、账本或登录后的数据；点按打开 God，锁屏上由系统先要求解锁。预告读数超过两小时不再显示倒计时，改为「打开 God」。
- **头像跟着账号走：**头像裁成 512 像素 JPEG 存在本机，同时保存到 God 服务器（`profile/avatar`），重装或换手机后自动拉回；服务器会再剥一遍元数据。0.17.0 之前登录的会话没有写入权限，第一次上传时提示重新登录一次，其他功能照常。
- **重置日历与 28 天挑战跟网页一致：**两页都在「功能 → 洞察」，紧跟 Token 额度。日历按网页手机版：周一开头的六周网格，每个格子直接列出当天每一项重置（左侧服务商颜色竖线，时间、平台、账号、额度项与「已过期 / 待核实」），点格子在下方展开当天明细；挑战页依次是标题与 Tibo 美西时钟、官方预告倒计时、重置提醒、28 格、所选日详情、同步说明。
- **Tibo 重置提醒像闹钟：**只在 Tibo 本人账号发出重置或发卡预告时响；用闹钟铃声重复响铃并在锁屏全屏显示，直到点「知道了」，没处理每 10 分钟再响，最多三轮。开启后常驻一条低优先级的「已开启」通知（前台服务），每 5 分钟检查一次。
- **克制：**不新增功能、不加教学文案，颜色和动效只用来帮助识别和反馈。按压时控件轻微下沉后回弹；切换 Tab 有轻触感反馈；进入和返回页面时有短暂的方向性过渡。系统关闭动画时全部跳过。

## 交互与文案

常用动作直接可达，复杂管理按需展开。一个明确入口应足以完成一个任务，不用口号和重复教学补偿布局问题。保留必要字段、单位、权限、错误和操作结果。

信息密度通过减少重复与组织层级实现，不能靠缩小触控区、隐藏关键动作或截断数值。

各Tab应像独立工作区：切换回来仍在原来的页面，详情返回原列表位置，重复点击当前Tab不重建或意外重载。刷新不能把阅读位置跳回开头，慢响应不能覆盖后续导航。

颜色只作辅助，文字名称和无障碍语义保留。大字体通过换行、堆叠调整，不能静默缩小关键金额。

## 数据和验证

空值不当零，来源旧数据不说实时。不能用合成数据掩盖真实读取失败。预览应用只用于合成视觉检查，完成后移除并回到正式App。

认证、权限、财务提交与回执行为不随视觉改动改变。各Tab的详情和分页上下文只保留在Activity内存中，退出账号清除。当前页的非敏感滚动坐标可随系统重建恢复，不保存分页游标、业务快照或表单；业务快照继续在后台清除。

每次改进先找到现行代码或真机上的实际问题，再做范围清楚的修改。构建、交互、真实读取与真实写入是不同验收层级；发布说明必须说明具体证据与限制。

## 当前优先工作

1. 导航与阅读上下文稳定性。
2. 可操作且不误导的错误/空值/陈旧反馈。
3. 按已有正式合同补齐高频功能，不制造看似可用的空入口。
4. 在真实使用证据支持下微调 Liquid Glass 的参数（透明度、模糊、色点），不再反复更换整体主题。

已知独立待办见 `FEATURE-PARITY.md` 和各版本发布说明。服务返回503、本人Passkey登记、尚未迁移的功能，不因UI测试通过而视为完成。
